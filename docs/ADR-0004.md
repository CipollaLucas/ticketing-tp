# ADR-0004 — Visibilidad, inventario y compra
Fecha: 2026-11-23. Issues #21/#22. Decisión del implementador pendiente de revisión.

Se mantiene lo integrado por PR #18: publicar metadatos no requiere zonas.
La alternativa de exigir inventario al publicar rompería ese contrato. No se agrega
un flag de venta independiente: comprar requiere published, inicio futuro e
inventario suficiente. La disponibilidad es una observación, nunca una reserva.
Configurar inventario exige draft futuro; las zonas/asientos son inmutables en este
incremento. La compra usará el mismo lock Event que publicación/configuración;
no se podrá despublicar un evento con ventas. Una venta confirmada no se modifica
ni elimina. Devoluciones se diseñarán en Etapa III y requerirán revisar unicidad
histórica versus venta activa. Monedas soportadas inicialmente: ARS, USD y EUR
(códigos ISO 4217); ampliar la lista requiere decisión explícita.

Un único backend modular y una transacción PostgreSQL mantienen atomicidad; no
se agregan colas, pagos ni transacciones distribuidas. Esto no completa la exigencia
arquitectónica de microservicios del TP: queda documentada como pendiente.
