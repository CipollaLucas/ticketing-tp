## Why
Etapa I exige mockups y una interfaz navegable para tres tipos de usuarios, coordinada con contratos API.

## What Changes
- Mockups de catálogo, detalle, registro/login, compra y mis tickets.
- Flujos de event owner (borrador/publicación) y administración (vista operativa).
- Design system y contratos de integración para un frontend React/TypeScript.

## Out of scope
No afirmar que checkout, pagos o emisión de tickets funcionan; usar estados de demostración explícitos hasta contar con API real.
